# Alice Client

Исследовательский Python-клиент для обмена текстом и аудио с Алисой через наблюдаемый WebSocket-протокол Uniproxy. Одна библиотека, четыре сценария и сохранённые имена исходных скриптов.

**Python 3.11+** · **Asyncio** · **CLI** · **Неофициальный проект**

[Быстрый старт](#быстрый-старт) · [Команды](#команды) · [Python API](#python-api) · [Проверки](docs/TESTING.md) · [Правовое уведомление](LEGAL_NOTICE.md)

> Проект не связан с Яндексом и не является официальным SDK. Используется недокументированный интерфейс; доступность функций зависит от сервера и прав аккаунта. История происхождения кода, включая сведения из прежнего README, открыто описана в [PROVENANCE.md](PROVENANCE.md).

## Возможности

| Сценарий | Команда | Результат |
| --- | --- | --- |
| Диалог | `python -m alice_client chat` | Ответ в терминале |
| Озвученный ответ | `python -m alice_client chat --audio` | Текст и аудиофайл |
| Синтез речи | `python -m alice_client tts "Привет"` | Аудио переданного текста |
| Распознавание | `python -m alice_client asr` | Текст с микрофона; нужны PyAudio, токен и ключ ASR |
| Вход в Яндекс | `python -m alice_client auth login --client-id YOUR_CLIENT_ID` | Токен в защищённом хранилище ОС |
| Вход с `.env` | `python yandex_login.py` | Браузерный вход и автоматическое сохранение токена в `.env` |
| Проверка прав | `python -m alice_client auth check` | Отдельные результаты Яндекс ID и умного дома |

Клиент сопоставляет ответы с запросами по `messageId`, собирает бинарные аудиочасти по `streamId`, ограничивает время ожидания и объём аудио. Запрос регистрируется до отправки, поэтому быстрый ответ не теряется. При закрытии соединения, отмене или таймауте ожидающие операции завершаются и освобождают ресурсы.

Получение текста или аудио не подтверждает доступ к конкретной версии модели, подписке или умному дому. Названия старых файлов со `speechkit` сохранены для удобства; это не реализация официального облачного SpeechKit SDK.

## Быстрый старт

Скачайте репозиторий и создайте отдельное окружение.

```bash
git clone https://github.com/Iversat/Alice-Client.git
cd Alice-Client
python -m venv .venv
```

Активируйте окружение: `.venv\Scripts\Activate.ps1` в PowerShell или `source .venv/bin/activate` в Linux/macOS. Если активация PowerShell недоступна, используйте `.venv\Scripts\python.exe` вместо `python` в командах ниже.

```bash
python -m pip install -e .
python -m alice_client chat --anonymous --text "Привет"
```

На Windows, если команда `python` не найдена, используйте `py` для создания окружения:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m alice_client chat --anonymous --text "Привет"
```

## Войти через сайт Яндекса и сохранить `.env`

Из папки проекта запустите:

```powershell
.\.venv\Scripts\python.exe yandex_login.py
```

Откроется **сайт Яндекса**, где нужно войти в свой аккаунт и подтвердить вход ползунком. Если браузер уже авторизован, достаточно выбрать нужный аккаунт и подтвердить. Python сам дождётся результата, получит токен, проверит его через Яндекс и сохранит в `.env` рядом со скриптом. **ClientID, регистрация приложения и ручное копирование токена для этого сценария не нужны.**

После сообщения «Готово. Токен сохранён» запускайте чат из той же папки:

```powershell
.\.venv\Scripts\python.exe -m alice_client chat
```

`--no-browser` показывает ссылку для самостоятельного открытия, `--wait 300` ограничивает ожидание. Ctrl+C отменяет ожидание. При отказе, ошибке или отмене существующий `.env` сохраняется. Повторный запуск скрипта позволяет заново привязать аккаунт.

Используется неофициальный протокол подтверждения входа Яндекс Passport, адаптированный по [AlexxIT/YandexStation](https://github.com/AlexxIT/YandexStation/blob/master/custom_components/yandex_station/core/yandex_session.py); уведомление об источнике — [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Скрипт использует только собственную временную сессию, не читает cookies из профилей браузера и не получает пароль пользователя. После подтверждения временная сессия обменивается на токен и очищается. Доступность этого интерфейса зависит от Яндекса.

`.env` содержит токен **открытым текстом**, исключён из Git и предназначен для локального использования. Существующие настройки и комментарии сохраняются. Приоритет токена: окружение процесса → `.env` в текущей папке → системное хранилище. `--anonymous` игнорирует все три источника. В Python используйте `YandexAliceClient(oauth_token=get_token())`.

**Живая проверка 21 октября 2026:** вход через сайт Яндекса выполнен, токен автоматически сохранён в `.env`; Яндекс ID подтвердил его действительность; чат без `--token-prompt` получил ответ. Официальный API умного дома вернул `403`: не следует считать, что этот токен имеет права `iot:view`/`iot:control` или что обычный ответ чата подтверждает управление устройствами.

Для разработчиков остаётся альтернативный официальный OAuth device flow со своим приложением: `yandex_login.py --oauth-app`. Этот дополнительный режим запрашивает ClientID и может сохранять refresh-токен. Его обновление: `yandex_login.py --oauth-app --refresh`. Команды `auth login` ниже сохраняют токен в системном хранилище, а не в `.env`.

## Дополнительно: официальное OAuth-приложение и системное хранилище

1. Зарегистрируйте своё приложение на [Яндекс OAuth](https://oauth.yandex.ru/). Для чтения умного дома укажите `iot:view`; для управления нужен отдельный доступ `iot:control`. Не запрашивайте лишних прав. Токен приложения для входа через Яндекс ID может иметь другой набор доступов.
2. Скопируйте **ClientID** (это идентификатор, а не токен аккаунта).
3. Запустите вход, откройте показанную страницу Яндекса, введите код устройства и подтвердите нужные доступы:

```bash
python -m alice_client auth login --client-id YOUR_CLIENT_ID
python -m alice_client auth status
python -m alice_client auth check
python -m alice_client chat --text "Привет"
```

Авторизация реализована по официальному [Device Authorization Flow Яндекса](https://yandex.ru/dev/id/doc/ru/codes/screen-code-oauth). Пароль вводится только на стороне Яндекса. Клиент не извлекает cookies браузера. Если для приложения требуется Client secret, передайте его через окружение `YANDEX_CLIENT_SECRET`; он не записывается клиентом. `YANDEX_CLIENT_ID` заменяет аргумент `--client-id`. `--no-browser` позволяет открыть страницу самостоятельно, `--wait 300` ограничивает ожидание.

Токен сохраняется через `keyring`: Windows Credential Manager, macOS Keychain или защищённый системный keyring Linux. При отсутствии подходящего хранилища вход с сохранением завершается ошибкой; в таком окружении доступны `YANDEX_OAUTH_TOKEN` и `--token-prompt`. Команда `auth login` не создаёт открытые файлы с токенами; отдельный `yandex_login.py` сохраняет `.env` по явному выбору пользователя.

```bash
# Сохранить уже имеющийся токен через скрытый ввод.
python -m alice_client auth import

# Обновить токен, выданный через auth login (при наличии refresh_token).
python -m alice_client auth refresh

# Удалить локальную копию. Это не отзывает доступ приложения у Яндекса.
python -m alice_client auth logout
```

`auth check` выполняет только чтение: отдельно обращается к Яндекс ID и [официальному API умного дома](https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-protocol). Вывод содержит успешность проверок и количество устройств/групп/сценариев, без имён, адресов и идентификаторов. Код выхода `1` означает, что хотя бы одна из проверок не прошла: у токена для умного дома может не быть доступа к Яндекс ID и наоборот. Это не означает, что весь токен недействителен.

Для использования токена в своём коде:

```python
from alice_client import YandexAliceClient, get_token

client = YandexAliceClient(oauth_token=get_token())
```

Если нужен именно текст токена, команда `python -m alice_client auth token --show` явно выводит секрет в stdout. Используйте её только в приватном терминале и не публикуйте вывод. Обычно достаточно `get_token()`.

В диалоге токен передаётся в `System.SynchronizeState` и `Vins.TextInput`, в TTS — в `TTS.Generate`. Сервер сам определяет доступные функции. Успешный OAuth-вход или ответ на «Привет» не доказывает, что недокументированный диалог использует аккаунт, подписку или умеет управлять домом. Токен с `iot:view` разрешает чтение; управление через официальный API требует `iot:control`. Анонимный режим не даёт доступа к данным личного умного дома. Для ASR по-прежнему требуется отдельный `YANDEX_ASR_KEY`.

## Команды

```bash
# Диалог: exit, quit или выход завершают сеанс.
python -m alice_client chat --token-prompt

# Один ответ в формате JSON.
python -m alice_client chat --anonymous --text "Привет" --json

# Текст и озвученный ответ. По умолчанию: responses/reply-001.opus и далее.
python -m alice_client chat --audio --token-prompt

# Синтез текста в файл. Без текста включается интерактивный режим.
python -m alice_client tts "Привет, мир" --output response.opus --token-prompt

# Справка по режиму.
python -m alice_client chat --help
```

Аудио сохраняется в том виде, в котором его прислал сервер: конвертация и автоматическое воспроизведение не выполняются. Повторное использование явно заданного `--output` заменяет файл по этому пути.

Режим CLI `chat --audio` получает текст ответа, затем отправляет его на синтез речи отдельным запросом. Это проверенный сценарий для анонимного соединения: встроенный аудиоответ на `voice_session=True` в реальной проверке не пришёл. Низкоуровневый аргумент API `is_tts_response=True` сохранён для исследования такого ответа; его доступность не гарантируется.

Для микрофона установите дополнительную зависимость и задайте доступный вам ключ в переменной `YANDEX_ASR_KEY`:

```bash
python -m pip install -e ".[audio]"
python -m alice_client asr --token-prompt --duration 30 --partial
```

Запись: **PCM16, mono, 16 кГц**, блок 1024 кадра, то есть 64 мс. Без `--duration` распознавание продолжается до Ctrl+C. Промежуточные результаты `--partial` идут в stderr, окончательные — в stdout. Ключ по умолчанию не подставляется. Правомерное получение токена и ключа остаётся за пользователем; проект не предоставляет права на закрытые или платные функции.

В Linux для сборки PyAudio могут понадобиться системные заголовки PortAudio и Python. Чат и синтез речи работают без установки PyAudio и без доступа к микрофону.

## Python API

```python
import asyncio

from alice_client import YandexAliceClient, get_token


async def main():
    async with YandexAliceClient(
        oauth_token=get_token(),
        request_timeout=10,
    ) as client:
        result = await client.send_text("Привет")
        print(result["response_payload"])


asyncio.run(main())
```

Контекстный менеджер открывает соединение, отправляет состояние клиента и закрывает ресурсы. Отправка состояния не означает подтверждения авторизации. Методы `send_text()` и `tts()` возбуждают `YandexAliceClientError`; таймаут — `AliceTimeoutError`. Ошибка больше не маскируется предположением о неверном токене.

Синхронный адаптер `YandexAliceClientPython` доступен из `alice_client.sync` и исходного `alice_client_terminal.py`. При переходе со старого кода учтите [изменения API](CHANGELOG.md).
