# Сообщения о проблемах

В голосовом режиме Whisper (`auto`) или Vosk (`ru`/`en`) обрабатывает микрофон локально. До триггера текст не отправляется Яндексу; после него распознанная команда передаётся сервису Алисы. При `--follow-up` следующие фразы в указанном окне тоже являются командами. Микрофонные записи не сохраняются; ответы сохраняются только с явным `--output`. Файлы для серверного `--backend yandex` отправляются на распознавание Яндексу.

`yandex_login.py` по явному выбору пользователя записывает токен и refresh-токен открытым текстом в локальный `.env`. Файл исключён из Git. Его нельзя публиковать или отправлять с архивом проекта; автоматическая синхронизация папки облачным диском распространяется и на него. Команда `auth login` остаётся альтернативой с защищённым системным хранилищем.

Не публикуйте OAuth-токены, ключи ASR, полный сетевой дамп, записи чужой речи и персональные данные в issue или pull request. Для обычной ошибки достаточно версии Python, команды без секретов, типа исключения и минимального примера с вымышленными данными.

Если сообщение содержит секреты или описание уязвимости с последствиями для других пользователей, используйте доступный приватный канал связи из [профиля автора](https://github.com/Iversat). Публичные issue не являются приватным каналом. Срок ответа и отдельная программа вознаграждений не обещаются.

Тесты используют значения `local-test-token` и `local-test-key`: это фиктивные строки, не учётные данные сервисов. Они не дают доступа к Яндексу.

Вход сохраняется в системном хранилище через `keyring` под сервисом `Alice-Client/Yandex-OAuth`, профиль `default`. OAuth-запросы выполняются только к заданным HTTPS-адресам Яндекса; HTTP-редиректы запрещены. `auth logout` удаляет локальную копию, а доступ приложения отзывается в Яндекс ID. `auth token --show` — явная операция вывода секрета; не используйте её в записываемом или публичном терминале.
