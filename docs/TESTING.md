# Проверка Alice Client

Дата локальной проверки: **20 октября 2026**. Среда: Windows, Python 3.12.10, websockets 16.1.1. Проверки других сред задаются в CI; его результат нужно смотреть в конкретном запуске, а не выводить из наличия YAML.

Локально для 0.4.1: **162 теста пройдены** на Windows / Python 3.14.6, включая установленные голосовые зависимости. В 0.4.0 было 148 тестов. Обычный CI без голосовых зависимостей пропускает три проверки с NumPy; остальные тесты используют подменённые устройства. Реальные проверки ниже выполнялись отдельно на компьютере пользователя.

## Автоматический RU/EN и два триггера — 0.4.1

Одна сессия `asr --lang auto` распознала последовательность русских и английских фраз из WAV без смены настроек:

| Исходная речь | Результат | Триггер |
| --- | --- | --- |
| «Алиса, сколько будет два плюс два?» | «Алиса, сколько будет 2, плюс 2?» | Алиса |
| “Alice, what is the capital of France?” | “Alice, what is the capital of France?” | Alice |
| «Алиса» отдельно | «Алиса» | Окно ожидания команды |
| “Alice” отдельно | “Alice” | Окно ожидания команды |

В `voice --file … --no-play` первые два запроса отправились Алисе и получили текст/TTS; отдельные триггеры не создавали пустых запросов. На английский вопрос сервис ответил по-русски «Русский язык такой сложный! Попробуйте вспомнить правила.» — корректный английский ASR **не означает поддержку английского диалога самим сервисом**.

Модель — локальный Whisper base, CPU/int8. На проверенных коротких записях обработка фразы заняла примерно 0,65–0,72 с после подготовки модели, дополнительно есть ожидание паузы около 0,9 с. Это измерение на данном компьютере, не гарантия задержки. Русский/английский текст в дополнительных файлах распознан в правильном языке; в одной русской фразе «хорошая погода» получилось «хорошие погода». Модель не безошибочна.

Также выполнен 15-секундный запуск микрофона с `--lang auto`, завершившийся штатно. Два языка и оба триггера в этом дополнении проверены на синтезированных контрольных аудиофайлах; новая живая двуязычная речь пользователя отдельно не подтверждена. Микрофонное аудио не сохранено.

Проверены границы слов у триггеров, отсутствие активации от упоминания Alice в середине фразы, ограничение буфера тишины, выбор только RU/EN, работа инференса вне asyncio и завершение активного декодирования при отмене. Одноязычные Vosk-режимы доступны явно через `--lang ru` / `--lang en`.

## Полная проверка речи — 21 октября 2026

| Проверка | Фактический результат |
| --- | --- |
| Один запрос, без токена / с токеном из `.env` | «Привет» → текстовый ответ в обоих режимах |
| Сессия, без токена | «Давай сыграем в города» → «Москва» → «Анталья» → «Хватит»; `session_id` сохранён |
| Сессия, с токеном | Та же последовательность → «Арциз»; завершение игры, `session_id` сохранён |
| TTS слова и предложения, оба режима | Ogg/Opus: «Привет» — 6002 байта; «Это проверка синтеза речи.» — 17779 байт |
| Русский Ogg/Opus → локальный ASR | «Алиса, сколько будет два плюс два?» → «алиса сколько будет два плюс два» |
| Русский WAV, независимый голос Microsoft Irina | «Привет. Это проверка распознавания речи. Сегодня хорошая погода.» — все слова распознаны |
| Английский WAV, Microsoft Zira | «Hello. This is a test of speech recognition. The weather is nice today.» — все слова распознаны |
| Английский TTS Яндекса, короткая фраза | «Hello, how are you today?» → «hello how are you to the»; ошибка распознавания зафиксирована |
| Микрофон на 10 секунд | FIFINE открыт и штатно закрыт; в первом ограниченном запуске речи не распознано |
| Настоящие команды пользователя через FIFINE | «Алиса, сколько будет два плюс два» и «Алиса, привет» — триггер и запрос распознаны, ответы получены |
| Физическое воспроизведение | После исправления WASAPI / 44,1 кГц пользователь подтвердил, что ответ слышен на «Станции Мини new» |
| Серверный ASR Яндекса | **Не проверен**: отсутствует отдельный `YANDEX_ASR_KEY`. OAuth-токен его не заменяет |

Изначально клиент не переносил `payload.header.session_id` из VinsResponse в следующий TextInput. После исправления проверена именно зависимость следующей реплики от предыдущей, а не только несколько ответов в одном соединении.

Во время проверки звук через WinMM/MME не был слышен, хотя поток завершался без ошибки. Прямой WASAPI первоначально отвергал частоту TTS 48 кГц: устройство использовало 44,1 кГц. После преобразования частоты и выбора WASAPI того же системного выхода измеренный пик Windows составил 0,678, а пользователь подтвердил слышимость. Громкость Windows и выбор системного устройства не изменялись. Дополнительно исправлен callback PortAudio: функция `void` должна возвращать `None`.

С токеном запрос «сколько будет два плюс два» возвращал поисковый фрагмент про доказательство «2 + 2 = 5», а не надёжный арифметический ответ. Поэтому успешный обмен и TTS не означают корректность содержания или доступ к определённой модели Алисы.

Эта таблица описывает проверки 0.4.0 с Vosk и явным выбором RU/EN; автоматический режим 0.4.1 описан выше. Тестовые файлы синтезированы, это не оценка качества ASR на большой выборке. До триггера микрофонные данные не отправляются Яндексу; исходная речь пользователя не сохранена.

Для повторной сетевой проверки: `python scripts/verify_services.py --output responses/verification`. Скрипт выполняет реальные запросы в двух режимах, сохраняет безопасный JSON-отчёт и тестовые TTS-файлы; он не включает микрофон и не выводит токены. Команды ручной голосовой проверки приведены в README.

## Автоматические проверки

```bash
python -m pip install -e ".[dev]"
python -m pytest --cov=alice_client --cov-report=term-missing
python -m ruff check .
python -m ruff format --check .
python -m pip check
python -m build
```

Тесты проверяют:

- мгновенный ответ, ответы в другом порядке и параллельные запросы;
- текст, Speak, бинарные аудиочасти и завершение потока;
- ошибки сервера, некорректный JSON, неправильные типы полей и лимит аудио;
- таймаут, отмену, разрыв соединения и освобождение ожидающих операций;
- обмен через настоящий WebSocket с локальным сервером и повторное подключение;
- синхронный адаптер и завершение его рабочего потока;
- PCM16-кадры ASR, частичные и окончательные результаты, EOF, запоздавшие ответы;
- остановку ASR и освобождение подменённого микрофонного драйвера;
- CLI, скрытый ввод, анонимный режим, JSON и сохранение файлов;
- ограниченный по времени сеанс ASR через локальный сервер с синтетическим PCM.
- OAuth polling, pending/slow_down, отказ, таймаут, проверку ответа и запрет HTTP-редиректов;
- хранение/удаление/обновление токена, приоритет источников и исключение секретов из ошибок;
- независимость доступов Яндекс ID и умного дома, отсутствие личных данных в диагностике.

Эти тесты не используют реальные учётные данные, не подключаются к Яндексу и не записывают микрофон. Синтетические данные не подтверждают качество распознавания настоящей речи.

## Реальный endpoint

Выполнены ограниченные запросы к `wss://uniproxy.alice.ya.ru/uni.ws` без OAuth-токена:

| Проверка | Наблюдение |
| --- | --- |
| WebSocket | Соединение установлено |
| Текстовый запрос «Привет» | Получен VinsResponse с карточкой ответа |
| TTS короткой тестовой фразы | Получено 20 435 байт аудио |

Дополнительная проверка исходного сценария `voice_session=True` получила текст, но не дождалась аудиопотока за пять секунд. Поэтому CLI `chat --audio` озвучивает текст отдельным запросом TTS. Для протокольного API `is_tts_response=True` сохранены ожидание встроенного потока и явный таймаут.

После исправления `alice_client_receiving_tts.py --anonymous --text "Привет"` получил реальный текст и сохранил **24 122 байта** аудио. Скрипт отдельного TTS также сохранил **11 099 байт**. Оба файла имеют заголовок OggS; автоматическая проверка контейнера не заменяет прослушивание.

Это исторический результат проверки 0.2.0, а не гарантия доступности интерфейса. На том этапе аккаунт, умный дом и микрофон не проверялись, аудиопоток не прослушивался. Актуальные результаты 0.4.0 приведены выше.

## Воспроизведённые ошибки исходной версии

База: коммит `d1d7f75cff9394f29a569da92b4fb8fb6e09ebb8`.

1. Мгновенная директива ответа приходила до создания ActiveRequest и терялась.
2. Корректный JSON-массив с ключевым словом directive вызывал TypeError вместо безопасного игнорирования.
3. Штатное завершение async-итератора WebSocket оставляло флаг подключения установленным.

Для исправленного поведения добавлены регрессионные тесты. Дополнительно проверены ранее не покрытые сценарии отмены, частичного аудио, ошибок отправки и микрофонного завершения.


## Прямой вход в аккаунт — 21 октября 2026

На Windows пользователя, в копии `Alice-Client-main` на рабочем столе:

1. `yandex_login.py --no-browser --wait 600` создал ссылку Яндекс Passport.
2. В браузере открыт сайт Яндекса; пользователь подтвердил вход ползунком.
3. Python получил токен, проверил его и автоматически записал `.env`.
4. `python -m alice_client auth status`: `env_file_token=true`, токен не печатался.
5. `python -m alice_client auth check`: Яндекс ID — успешно; официальный API умного дома — HTTP 403.
6. `python -m alice_client chat --text "Привет"`: получен ответ с автоматически загруженным токеном.

Тесты также проверяют разрешённый адрес ссылки, ожидание подтверждения, отказ, отмену, таймаут, фильтрацию cookies собственной сессии, проверку токена до сохранения, отсутствие секретов в ошибках, сохранение остальных настроек `.env` и загрузку токена клиентом. Cookies существующего браузера не извлекаются. Ни токен, ни ссылка подтверждения не включены в этот отчёт.

Действительность токена в Яндекс ID и получение ответа диалога не доказывают управление умным домом. На этапе проверки входа микрофон ещё не проверялся; результаты последующей проверки 0.4.0 приведены выше.
